# V1 — Bound the public claims against verified evidence

## Why

The README describes hybrid search, a semantic reranker, Document Intelligence
layout extraction, Azure OpenAI function calling, a ~120 MB distroless image and a
one-command AKS deploy. CI proves a **narrower** thing than that, and the gap was not
written down in one place. This task records exactly what is verified, by what, and
what is not.

## What actually runs

`.github/workflows/ci.yml`, on every push and pull request:

1. `ruff check .`
2. `ruff format --check .`
3. `python -m pytest -v --tb=short -m "not integration"`
4. **On `main` only:** build the image and push it to GHCR.

The marker expression is itself the boundary. `-m "not integration"` excludes every
test that would require Azure, so no receipt in this repository includes a live Azure
call.

## Claim → evidence map

| README claim | Verified here? | By what |
|---|---|---|
| Three chunking strategies (recursive, semantic, hierarchical) | **Yes**, unit level | `TestChunking` — 5 tests over real chunker code |
| Financial query expansion (YoY, EBITDA, CAGR, tickers) | **Yes**, unit level | `TestRetrieval` — 3 tests |
| API surface: health, query, ingest, index, retrieve, agent, CORS | **Yes**, unit level | `TestAPIEndpoints` — 7 tests, including input validation |
| Hybrid search + semantic reranker | **No** | Requires live Azure AI Search. The index/config code is present; its behaviour is unmeasured |
| Document Intelligence layout extraction (OCR, tables) | **No** | Requires live Azure Document Intelligence |
| Azure OpenAI embeddings and chat generation | **No** | Requires live Azure OpenAI |
| Agentic function calling with three tools | **No** | Only the endpoint's request validation is exercised, not a real tool-calling loop |
| SSE streaming | **No** | Request-shape validation only; no live token stream |
| "~120 MB distroless" image | **Partly** — the image **builds**; the size was never measured | Dockerfile uses `gcr.io/distroless/python3-debian12` |
| "One-command deploy to any AKS cluster" | **No** | `k8s/` manifests and `infra/` Terraform exist but have never been applied |
| Terraform-provisioned Azure AI Foundry resources | **No** | The configuration is present; no plan or apply is recorded |

## The honest summary

This repository demonstrates an **implemented and unit-verified FastAPI RAG
application**: chunking, query expansion, request validation, error handling, a
container build and a CI pipeline. It does **not** demonstrate measured retrieval or
answer quality, because nothing here has called Azure.

That distinction is the whole point of recording it. "Hybrid search with a semantic
reranker" is a description of code that exists; it is not evidence that retrieval
works.

## What would close the gap

An integration run against real services, recording: documents ingested and chunked,
a fixed query set, per-query retrieved source IDs, and the Search diagnostic showing
whether the semantic reranker was actually applied. Until that exists, this stays a
reference implementation.
